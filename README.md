# Batfiles

A dotfiles manager built around plain files and explicit composition.

Keep ordinary files in Git, declare where they belong in `batfiles.toml`, and
run `batfiles sync`. Batfiles supports installation, repository composition,
machine-specific configuration, bootstrap, and self-update. There is no hidden
ownership database or per-repository install hook.

## Installing

On Linux or macOS, install batfiles to `~/.local/bin` and clone your dotfiles:

```sh
curl -fsSL https://batfiles.dev/install.sh | sh -s -- clone https://github.com/me/dotfiles
```

On Windows, use PowerShell 7 (`pwsh`):

```powershell
& ([scriptblock]::Create((irm https://batfiles.dev/install.ps1))) clone https://github.com/me/dotfiles
```

Windows installs to `%LOCALAPPDATA%\Programs\batfiles`. `clone` creates the
repository directory, `~/dotfiles` by default, and refuses one that already
exists; omit the `clone` command and its URL to install only the binary. Installers verify downloads against the
release's `SHA256SUMS` and leave shell startup files alone; ensure the install
directory is on your `PATH`. See [installer options](docs/installer.md#hosted-installer)
for version pinning and alternate locations.

An existing checkout can use its `install.sh` or `install.ps1`, generated by
`batfiles init`: the [stub](docs/installer.md#leaf-stub) gets batfiles if
needed and synchronizes that checkout. Add missing stubs with `batfiles init --stubs`.

[Releases](https://github.com/abatkin/batfiles/releases) also provide bare
binaries for Linux, macOS, and Windows. To build from source with the pinned
Rust toolchain, run `cargo build --release`; the binary is in `target/release/`.

```sh
batfiles update --check  # check for a release
batfiles update         # install the latest stable release
```

Updates happen only when requested. See [`update`](docs/commands/update.md#update).

## Example

Start with `batfiles init` in an empty directory, or explore
[the sample repository](https://github.com/batfiles-samples/simple-dotfiles).
A minimal repository needs a `batfiles.toml` and the files it references:

```text
dotfiles/
├── batfiles.toml
├── shell/zshrc
└── editor/nvim/init.lua
```

```toml
[[actions]]
type = "symlink"
id = "zshrc"
group = "shell"
source = "shell/zshrc"
dest = "~/.zshrc"

[[actions]]
type = "symlink"
id = "nvim"
group = "editor"
source = "editor/nvim"
dest = "~/.config/nvim"
```

From the repository root:

```sh
batfiles sync --dry-run               # preview installation
batfiles sync                        # install in declaration order
batfiles sync -v                     # include unchanged and skipped actions
batfiles apply-action --id nvim       # apply one action
batfiles sync --skip-group editor     # skip a group for this run
batfiles disable-group editor        # skip it until enabled again
batfiles enable-group editor
```

A run names each change on standard error, and anything in the way is backed up
beside it first:

```console
$ batfiles sync
backed up /home/you/.zshrc to /home/you/.zshrc.batfiles-backup-20260929T142233Z
linked /home/you/.zshrc -> /home/you/dotfiles/shell/zshrc
linked /home/you/.config/nvim -> /home/you/dotfiles/editor/nvim
```

Running it again prints nothing, because correct destinations are left alone.
`--no-overwrite` skips conflicts instead and `--interactive` asks. See
[destination safety](docs/safety.md#replacing-what-is-already-there).
A dry run leaves installation content alone but can run dynamic-variable
commands and write bookkeeping; see [dry-run behavior](docs/cmdline.md#dry-run-behavior).

For machine-specific actions, declare `[vars]` defaults and add `when` or
`unless` [conditions](docs/repoformat.md#conditions). For example, `work = "false"`
with `when = "work"` is enabled by `batfiles vars set work true` or by
`batfiles sync --var work=true` for one run.

Repository discovery and alternate locations follow
[location selection](docs/environment.md#location-selection). For a larger,
tested example, see [the acceptance fixture](tests/fixtures/leaf).

## Supported features

Supported actions: `symlink`, `symlink-dir`, `create-dir`, `copy`, `copy-dir`, `fetch-file`, `fetch-archive`, `git-clone`, `git-clone-list`, `include-remote`.

| Need | Feature |
| --- | --- |
| Link files or directories | `symlink`; `symlink-dir` links direct children |
| Seed editable content | `copy`, `copy-dir`; `--refresh-content` rebuilds seeds |
| Create a directory | `create-dir` |
| Download content | `fetch-file`, `fetch-archive`, with optional SHA-256 verification |
| Manage repositories or plugin lists | `git-clone`, `git-clone-list` |
| Compose repositories | `[remotes]` supplies content; `include-remote` includes actions |
| Choose content per machine | Groups, persistent disables, run-only skips, variables and conditions |
| Discover machine values | Cached [dynamic variables](docs/repoformat.md#dynamic-variables) |

See the [action reference](docs/repoformat.md#actions) for fields, filters, and
examples. **Symlink actions require Unix**; executing them on Windows fails.
Directory, copy, download, and Git actions support Windows. CI tests Linux,
macOS, and Windows.

## Product principles

- **Keep repositories plain.** Ordinary files in Git, explicit actions, and
  [strict manifest validation](docs/repoformat.md#reading-the-manifest).
- **Make composition explicit.** Your repository chooses its sources and the
  actions it includes; inclusion is [one level deep](docs/actions/include-remote.md#include-remote).
- **Keep installation predictable.** Actions run in declaration order; authors
  own overlapping destinations. See [selection and dry-run](docs/cmdline.md).
- **Preserve user content.** Apply [destination safety](docs/safety.md), with
  backups, editable seeds, and conservative Git updates.
- **Keep automation explicit.** Prompts and binary updates require a request;
  releases can be [self-hosted](docs/contributing/distribution.md#self-hosting).
- **Keep state small and inspectable.** Machine choices and disposable caches
  have separate [state files](docs/state.md).

## Development

Start with [AGENTS.md](AGENTS.md) for the branch workflow and canonical commands,
and [architecture](docs/contributing/architecture.md) for implementation and test design.
Run `task ci` for the full checks; [Taskfile.yml](Taskfile.yml) is authoritative.

Alongside the pinned Rust toolchain, install [go-task](https://taskfile.dev),
[ShellCheck](https://www.shellcheck.net/), and `cargo install cargo-deny cargo-xwin --locked`.
PowerShell lint requires PSScriptAnalyzer where `pwsh` is installed; otherwise
that check is skipped. `cargo-xwin` fetches and caches the Windows SDK for lint.
Container acceptance uses Docker or Podman and reports a skip if neither works.
The documentation tasks and `task test` fetch the pinned mdBook and lychee on
first use; `task docs:serve` previews the book. See [documentation authoring](docs/contributing/authoring.md)
and [release management](dist/README.md) for publishing.
